提权

bob -> secretote

在家目录下有个limpieza.sh

它的核心作用是：定期自动清理系统临时目录中的特定垃圾文件（如临时文件、备份文件、缓存文件等） 。

可以看到执行了limpieza.sh但是UID是1001而1001就是bob所以这条路行不通

换条路线，继续使用hydra爆破剩下的两个用户secretote和debian

查看当前进程的 Linux Capabilities

原因分析

现代 Linux 引入了 Capabilities 机制，将传统 root 用户的特权拆分为了几十个细分权限。在当前的内核安全模型中，Capabilities 的优先级高于 UID（即能力大于身份）。

  • ​man​​ 命令的沙盒化（Sandboxing） ​：现代系统的 man 在执行时，为了防止被恶意提权，会主动丢弃绝大部分特权。它派生出的子 Shell 继承了这一限制。

  • Current 集合被挖空​：我们的 Current​（当前有效能力集）里​只有 ​cap_setgid​​ 和 ​cap_setuid​。

  • 关键能力缺失：

    • 缺失 cap_net_admin​：导致无法打开 netlink 套接字，因此 ip a 报错。
    • 缺失 cap_dac_override​：导致无法绕过文件系统的常规权限检查（DAC）。即使我们是 root 身份，由于没有这个能力，依然无法进入属于 bob​ 且权限为 700 的目录。
