hosts写入

gogs.craft.htb下有个craf的项目。

在对提交历史进行查看的时候发现了历史用户。

这个用户呢依然是能够登录上去的。

dinesh

4aUh0A8PbVJxgd

在添加对错误 ABV 值的修复这个修复里面dinesh用户使用eval。这个函数呢会导致rce。

RCE

这里给git下来分析源码。

之前的eval是在craft_api/api/brew/endpoints/brew.py这个文件里面的。

这里的​eval可以执行rce。但是这道题的接口是有鉴权的需要token。

同时在tests文件夹下面有个test.py

这个脚本是用于测试 Craft API 身份认证、Token 有效性，以及啤酒数据创建和 ABV 数据校验的测试脚本。

我们只需要修改下就能利用了。

这里的payload执行了反弹shell。

是root权限，但是是在docker里面的需要逃逸到宿主机。

提权

docker root -> 宿主机 gilfoyle

/opt路由下面有源码，同时craft_api下面有个settings.py配置文件，里面包含了数据库的账号密码

同时app下面还有个dbtest.py查看源码发现进行了sql查询。

那么我们改下sql语句查询数据库。

有个craft数据库，这里需要改下result = cursor.fetchone()为result = cursor.fetchall()因为数据表返回的肯定不是一行。

一个brew表一个user表，下面直接查看user表的内容

获取到了其它用户的凭证。尝试登录发现gilfoyle有个私人项目

里面直接包含了ssh 密钥。我们直接git下来

但是存在passphrase需要爆破下密码，爆破无果后尝试了用户的密码发现可以登录。

‍

gilfoyle -> root

gilfoyle用户家目录下有个.vault-token文件

目前不知道是什么

上面搜索发现是HashiCorp Vault

这里就回到gogs里查找信息了发现里面有个vault文件夹和文件名很相似。进去之后有个secrets.sh

这段 Bash 脚本是用于配置 HashiCorp Vault 的 SSH Secrets Engine（SSH 密钥管理引擎） ，创建一个名为 ​root_otp​ 的 SSH 一次性密码（OTP）角色。它的核心作用是：让 Vault 为 SSH 登录生成一次性密码，用户通过这个密码进行 SSH 身份认证，而不需要直接分发 root 用户的固定密码或私钥。

它会调用 Vault SSH OTP 模式，自动完成一次性密码获取和 SSH 登录流程
